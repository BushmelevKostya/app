## Анализ текущего состояния проекта

Проект представляет собой полнофункциональное веб-приложение для управления базой данных фильмов с использованием следующего стека технологий:

### Backend
- **Java 17** с **Spring Boot 3.3.4**
- **PostgreSQL** в качестве СУБД
- **Redis** для кэширования
- **MinIO** для хранения файлов
- **WebSocket** для real-time обновлений

### Frontend
- **Angular 19** (standalone компоненты)
- **TypeScript 5.8**
- **RxJS** для работы с асинхронными данными

### Инфраструктура
- **Docker Compose** для оркестрации сервисов
- **Gradle** как система сборки

## Выявленные проблемы

### 1. Архитектурные проблемы

- **Нарушение принципа разделения ответственности**: Контроллеры содержат бизнес-логику вместо делегирования её сервисам
- **Отсутствие сервисного слоя**: Всего 2 `@Service` класса, основная логика в контроллерах
- **Прямая работа с репозиториями**: Контроллеры напрямую обращаются к множеству репозиториев
- **Нарушение принципа единственной ответственности**: `HomeComponent.ts` содержит 670 строк кода
- **Отсутствие DTO**: Использование entity для передачи данных между слоями

### 2. Безопасность

- **Небезопасная настройка CORS**: `@CrossOrigin(origins = "http://localhost:4200")` хардкод на всех контроллерах
- **Примитивная авторизация**: Хранение статуса авторизации в `sessionStorage` на клиенте
- **Отсутствие Spring Security**: Собственная реализация аутентификации без использования стандартных механизмов
- **Хранение паролей**: Использование простого хеширования без salt через `PasswordUtil`
- **Отсутствие JWT токенов**: Передача email в URL (`/api/action/{email}`)

### 3. Тестирование

- **Отсутствие тестов**: Нет unit-тестов для backend (только `testImplementation` в зависимостях)
- **Отсутствие E2E тестов**: Нет интеграционных тестов для критических сценариев
- **Отсутствие покрытия тестами**: Нет инструментов для измерения покрытия (JaCoCo)

### 4. База данных

- **DDL на автогенерации**: `spring.jpa.hibernate.ddl-auto = update` - не подходит для production
- **Отсутствие миграций**: Нет Flyway/Liquibase для версионирования схемы БД
- **Неоптимизированные запросы**: Отсутствие анализа производительности запросов
- **Отсутствие индексов**: Не проанализированы узкие места в запросах

### 5. Инфраструктура и DevOps

- **Отсутствие CI/CD**: Нет GitHub Actions/GitLab CI для автоматических проверок и развертывания
- **Закомментированный сервис app**: В `docker-compose.yml` закомментирован контейнер приложения
- **Отсутствие мониторинга**: Нет интеграции с Prometheus, Grafana
- **Отсутствие централизованного логирования**: Нет структурированного логирования
- **Хардкод конфигурации**: Переменные окружения не полностью вынесены

## План рефакторинга

## Этап 1. Архитектурный рефакторинг и безопасность

### Цель
Повысить надежность, безопасность и сопровождаемость проекта за счет внедрения чистой архитектуры и современных практик безопасности.

### Задачи

#### 1.1. Внедрение Spring Security и JWT-аутентификации
- Добавить зависимости Spring Security и JWT библиотеки
- Реализовать JWT-based аутентификацию вместо передачи email в URL
- Создать `SecurityConfig` с настройками CORS, CSRF, фильтрами
- Реализовать `JwtAuthenticationFilter` для проверки токенов
- Создать `AuthenticationService` для login/register
- Обновить frontend для работы с JWT (interceptor для добавления токена в заголовки)

#### 1.2. Разделение на слои (Layered Architecture)
- **Создать сервисный слой**: Выделить бизнес-логику из контроллеров в сервисы
  - `MovieService` - работа с фильмами
  - `UserService` - управление пользователями
  - `NotificationService` - работа с уведомлениями
  - `FileService` - работа с файлами и MinIO
  - `ImportService` - логика импорта данных
- **Создать DTO слой**: Разделить модели для API и БД
  - Request DTO: `MovieCreateRequest`, `MovieUpdateRequest`, `UserRegistrationRequest`
  - Response DTO: `MovieResponse`, `UserResponse`, `PageResponse<T>`
  - Использовать MapStruct или ModelMapper для маппинга
- **Рефакторинг контроллеров**: Оставить только обработку HTTP-запросов, делегировать логику сервисам

#### 1.3. Настройка безопасного CORS
- Вынести конфигурацию CORS в `application.properties`/`application.yml`
- Убрать `@CrossOrigin` из контроллеров, настроить глобально в `SecurityConfig`

#### 1.4. Улучшение обработки ошибок
- Создать единую систему обработки исключений с `@RestControllerAdvice`
- Реализовать иерархию custom exceptions (` BusinessException`, `ResourceNotFoundException`, `ValidationException`)
- Создать стандартизированный формат ответов с ошибками (`ErrorResponse` DTO)

#### 1.5. Покрытие unit-тестами критической логики
- Написать unit-тесты для сервисного слоя (Mockito)

## Этап 2. Рефакторинг базы данных

### Цель
Привести структуру БД к документированному и эффективному состоянию, обеспечить версионирование схемы и оптимизацию запросов.

### Задачи

#### 2.1. Анализ и оптимизация схемы БД
- Провести аудит текущей схемы БД:
  - Проверить ограничения целостности (foreign keys, unique constraints)
  - Проанализировать типы данных и nullable поля
  - Проверить правильность каскадных операций
- Нормализация данных (при необходимости):
  - Проверить соблюдение 3NF
  - Выделить справочные таблицы при необходимости
- Добавить аудит полей (`created_at`, `updated_at`, `created_by`, `updated_by`)

#### 2.2. Оптимизация производительности запросов
- Провести анализ с помощью `EXPLAIN ANALYZE` для часто используемых запросов
- Добавить индексы на часто запрашиваемые столбцы:
  - `movies(name, creation_date, mpaa_rating, genre)`
  - `movie_users(email)`
  - `notifications(approved, user_email)`
- Оптимизировать N+1 запросы через `@EntityGraph` или fetch joins
- Настроить pagination для больших выборок данных
